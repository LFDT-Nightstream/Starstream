# Starstream WIT worlds

Each Starstream contract is described by its own bespoke [WIT world][world],
importing builtins, Utxos, and so on used by the contract and exporting Utxos
and coordination scripts defined in the contract.

The shape of those imports and exports are described here and define the
interface between the Starstream runtime (host) and Starstream contract (guest).

[raw-wit]: https://github.com/LFDT-Nightstream/Starstream/tree/main/starstream-to-wasm/wit
[world]: https://component-model.bytecodealliance.org/design/worlds.html

## Exporting Utxos

Contracts which export Utxos use types from `starstream:std/utxo-context`:

<CodeBlock language="wit">{utxo_context_wit}</CodeBlock>

Each Utxo declared in the contract is represented as a distinct exported interface with an arbitrary name.
An exported interface represents a Utxo if it declares `resource utxo`.
Each Utxo also has a `record storage` describing its memory and `get-storage` (save) and `set-storage` (load) functions.

Exported functions receive a `utxo-context` supplied by the runtime.

`main fn`s are static methods on the `resource utxo`.

For example:

```wit
world root {
    import starstream:std/utxo-context;

    export my-utxo: interface {
        resource utxo {
            my-main-fn: static func(ctx: borrow<utxo-context>) -> utxo;
        }

        record storage {
            my-field: s32,
        }

        get-storage: func(self: borrow<utxo>) -> storage;
        set-storage: func(storage: storage) -> utxo;
    }
}
```

## Importing Utxos

Contracts which import Utxos do so by importing interfaces containing a `resource utxo`.
If needed, the import may also include `downcast` and `upcast` methods, which
the runtime will provide.

For example:

```
world root {
    import my-utxo: interface {
        use starstream:std/builtin.{utxo as builtin-utxo};

        resource utxo {
            my-main-fn: static func() -> utxo;
        }

        downcast: func(self: builtin-utxo) -> option<utxo>;
        upcast: func(self: utxo) -> builtin-utxo;
    }
}
```

Note that a contract which contains both a Utxo and a coordination script that uses it may export and import the same Utxo.

## Exporting coordination scripts

Coordination scripts are top-level function exports:

```wit
world root {
    export my-coordination-script: func();
}
```

## Cardano support

Starstream contracts may explicitly `import` the `cardano` interface to access Cardano-specific information.
Such contracts become limited to the Cardano chain.
For example:

```starstream
import { blockHeight } from starstream:std/cardano;

script fn myCoordinationScript() -> s64 {
    runtime blockHeight()
}
```

## Arbitrary WIT

Starstream contracts may import an arbitrary `namespace:package/interface` if the WIT is available at compile time.
Such contracts must be linked with an implementation in some way before being passed
to a standard Starstream runtime, which will not have an implementation of those imports.
